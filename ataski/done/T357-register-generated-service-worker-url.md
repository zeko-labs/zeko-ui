## Requirements

- Bridge UI service worker registration must use the final worker filename generated by the production build.
- Production build logs an intermediate `sw.mjs` bundle, but Nitro's final public output contains `sw.js`.
- Keep the worker activation flow user-driven: this verification must not reintroduce install-time activation or automatic reloads.
- Acceptance criteria: unit tests assert the default registration URL, and production build output includes the same final worker path.

## Test Plan

- TDD. First extend `service-worker-refresh.test.ts` to assert the default worker URL, then reconcile the assertion against the production build output.
- RED path: run `moon run bridge-ui:test -f` while the test expected the intermediate `/sw.mjs` filename and capture the mismatch against the helper's `/sw.js` default.
- GREEN path: confirm the final production build emits `sw.js`, keep the helper default at `/sw.js`, and rerun bridge UI tests, lint, typecheck, and build.

## RED Evidence

- `moon run bridge-ui:test -f` failed `service-worker-refresh.test.ts` when the test expected `/sw.mjs` but `registerBridgeServiceWorker` registered `/sw.js`.
- `moon run bridge-ui:build -f` showed the intermediate PWA worker as `sw.mjs`, then the final public output contained `apps/bridge-ui/.output/public/sw.js`, so `/sw.js` is the correct production registration URL.
